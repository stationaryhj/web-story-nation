# Q&A — 사이드바 메뉴 개편 (2026-07-15)

관련 계획: `docs/plan/plan-20260715-sidebar-menu-restructure.md`

## Q1. 모바일 GNB에도 동일 반영 ✅ 답변 완료

**상태**: ✅ 답변 완료 (2026-07-15, 안 1 채택)
**요약**: 사이드바 항목은 `navConfig.ts` 단일 소스를 데스크톱 사이드바와 **모바일 하단 GNB가 공유**한다. 요구사항대로 바꾸면 모바일 GNB에서도 '내 작업실'이 사라지고 '상점'이 추가된다.

**선택지**:

1. **동일 반영 (기본 가정)** — 데스크톱/모바일 메뉴 일관 유지, config 한 곳만 수정.
2. **데스크톱만 변경** — config를 분리해야 하므로 구조 변경 필요(비권장).

**답변**: 1번 동일 반영

## Q2. '만들기' 클릭 동작 변경 확인 ✅ 답변 완료

**상태**: ✅ 답변 완료 (2026-07-15, 안 1 채택)
**요약**: 현재 '만들기'는 채팅 모드 선택 모달(`chatModeSelect`)을 여는 액션이다. `/my-characters`(내 작업실) 라우트로 바꾸면 **모달 대신 페이지 이동**하며, 해당 페이지에 있을 때 '만들기'가 활성(하이라이트) 표시된다. 모달 자체는 `/my-characters` 페이지 내부에서 계속 쓰이므로 유지한다.

**선택지**:

1. **라우트 이동으로 전환 (기본 가정, 요구사항 해석)** — '만들기' 클릭 → `/my-characters` 이동.
2. 다른 의도가 있다면 기입.

**답변**: 1번

## Q3. 사이드바 '상점' 로그인 게이팅 ✅ 답변 완료

**상태**: ✅ 답변 완료 (2026-07-15, 안 1 채택)
**요약**: 톱바의 펜충전(상점) 아이콘은 미로그인 클릭 시 로그인 모달을 띄웠다. 사이드바 '상점'도 동일하게 `requireLogin: true`로 둘지 확인.

**선택지**:

1. **동일 게이팅 유지 (기본 가정)** — 미로그인 클릭 시 로그인 모달.
2. 비로그인도 상점 페이지 진입 허용.

**답변**:  1번

**답변 반영**: 기본 가정(각 1번)과 다르면 `plan-20260715-sidebar-menu-restructure.md` 해당 단계를 수정 후 구현. 기본 가정대로면 계획 그대로 진행.
